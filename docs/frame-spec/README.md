# 프레임 틀 만들기

외주 디자이너에게 넘길 프레임 규격서와 예시를 그려내는 것들이다.
그림 파일 자체는 저장소에 두지 않는다 — 다 합쳐 4MB 가 넘고, 여기서 언제든 다시 뽑을 수 있다.

## 돌리는 법

```
node docs/frame-spec/make-guide.js       규격서 한 장
node docs/frame-spec/make-examples.js    예시 프레임 두 종과 미리보기
node docs/frame-spec/make-blank.js       장식 없는 흰 바탕 틀
```

내보낼 곳을 인자로 줄 수 있다. 안 주면 바탕화면 `output\분경5컷_프레임_틀\` 로 간다.

```
node docs/frame-spec/make-guide.js D:\작업\프레임
```

크롬으로 캔버스에 그린다. 설치 위치를 못 찾으면 `CHROME_PATH` 로 알려주면 된다.
`puppeteer-core` 는 `server/node_modules` 것을 빌려 쓰므로, 먼저 `server` 에서 `npm install` 이 돼 있어야 한다.

## 나오는 것

| 파일 | 무엇 |
|---|---|
| `01_틀_치수가이드.png` | 규격서. 칸 좌표·크기·잘리는 자리·디자인 가능한 자리 |
| `02_예시A_학과띠.png` | 예시 A — 어두운 바탕. 사진 칸이 실제로 뚫린 납품 형식 |
| `03_예시A_미리보기.png` | A 에 예시 사진을 채운 모습 |
| `04_예시B_필름.png` | 예시 B — 밝은 필름 바탕 |
| `05_예시B_미리보기.png` | B 에 예시 사진을 채운 모습 |
| `06_빈틀_흰바탕.png` | 작업 바탕. 흰 바탕에 사진 칸 다섯 개만 뚫려 있다 |
| `07_빈틀_미리보기.png` | 빈 틀에 예시 사진을 채운 모습 |

`의뢰서.md` 를 함께 넘긴다. 디자이너가 읽을 문서다.

## 규격

`geom.js` 한 곳에서 정한다. 여기를 고치면 세 스크립트가 함께 따라온다.

| 항목 | 값 |
|---|---|
| 캔버스 | 1200 × 1800 px (4 × 6in, 300dpi) |
| 인화 용지 | **100 × 148 mm** — 캔버스보다 작다 |
| 흰 테 | 위아래 83 px (7.0 mm) · 좌우 47 px (4.0 mm). 흰색으로 비운다 |
| 사진 칸 | 450 × 430 px (38.1 × 36.4 mm) |
| 여백 | 좌우 58 px · 위아래 72 px (흰 테 안쪽) |
| 간격 | 가로 90 px · 세로 100 px |

용지가 캔버스보다 작아 세로가 더 많이 잘린다 (4.4 mm 대 1.6 mm). 위아래 테를 더 넓게 잡은 것은 그래서다.
바탕을 가장자리까지 채우는 도련 방식이 아니다 — 인화기가 정확히 자르지 못하면 채운 쪽은 잘린 자리가
그대로 보이는데, 흰 테는 조금 틀어져도 원래 그런 디자인으로 보인다.

캔버스를 용지 크기로 바꾸지 않는 이유는 앱이 4 × 6 비율로 사진을 잘라 두기 때문이다.
캔버스만 바꾸면 화면에서 본 구도와 종이에 나온 구도가 어긋난다.

좌우와 위아래 여백을 따로 둔다. 판이 2:3 이고 칸도 2열 3행이라, 사방을 똑같이 주면
칸이 반드시 세로로 길어진다. 가로를 더 길게 하려면 좌우 쪽만 좁혀야 한다.

## 앱 코드와의 관계

이 값들은 **아직 앱에 반영되지 않았다.** 앱은 `client-src/src/lib/frame.ts` 의 값
(사진 549 × 560, 안전선 개념 없음)으로 돌고 있다.

실물 프레임을 받아 좌표가 확정되면 `frame.ts` 를 고치고, 그때 `geom.js` 도 같은 값으로 맞춘다.
맞는지는 `scripts/check-frame.js` 로 잰다 — 그쪽은 `frame.ts` 를 직접 읽는다.

## 확인 안 된 것

흰 테 폭은 인화를 한 번 해보기 전에 정한 값이다. 실제로 더 잘리면 geom.js 의 SAFE_X / SAFE_Y 를 키운다.

용지 크기(100 × 148 mm)는 확정됐다.
